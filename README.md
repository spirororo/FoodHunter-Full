## О проекте
Приложение для поиска блюд по названию и просмотра детальной информации о рецепте.

Стек проекта:
- Compose
- Navigation Compose
- ViewModel + StateFlow + SharedFlow + Flow
- Coroutines + viewModelScope
- Retrofit
- Room
- Hilt

Используемое API: [TheMealDB](https://www.themealdb.com/api.php)

Основные эндпоинты:
- `GET /api/json/v1/1/search.php?s=` — поиск блюд по названию
- `GET /api/json/v1/1/lookup.php?i=` — получение полной информации о блюде по `id`

## Что сделано в ДЗ 4
- Реализовано 2 основных экрана: поиск и детали блюда.
- Подключена Navigation Compose с переходом на экран `Dish/{id}`.

- Подключён Hilt для DI.

Как проверить сценарий из ДЗ 4:
1. Запустить приложение.
2. Найти блюдо, например `chicken`.
3. Открыть любое блюдо.
4. Перейти на вкладку истории и убедиться, что блюдо сохранилось.
5. Перезапустить приложение и проверить, что история сохранилась.

## Что сделано в ДЗ 6

Реализована реактивная Flow-архитектура для экрана поиска.

### Источники данных (4 независимых):
1. `_query: MutableStateFlow<String>` — строка поиска (UI)
2. `_sortOrder: MutableStateFlow<SortOrder>` — режим сортировки (UI)
3. `historyStorage.watchHistory(): Flow<List<Dish>>` — история из Room (data layer)
4. `_searchTrigger: MutableSharedFlow<Unit>` — ручной поиск / retry (поток пользовательских действий)

### Реактивная цепочка

```
_query → map(trim+version) → debounce(500) → distinctUntilChanged
       → filter(versionCheck) → map(Auto) ─────────────────────────┐
                                                                     ├→ merge → flatMapLatest(buildSearchFlow)
_searchTrigger → map(Manual) ──────────────────────────────────────┘          → rawSearchState
                                                                                       │
_sortOrder ─────────────────────────────────────────────────────────────────────────────┤
                                                                                       ├→ combine → HomeScreenState
historyStorage.watchHistory() (Room) ──────────────────────────────────────────────────┘
```

- Автопоиск: пользователь вводит текст → после 500ms `debounce` запускается поиск; `filter` отсекает устаревшие авто-запросы, если пользователь уже нажал «Найти»
- Ручной поиск/retry: нажатие кнопки «Найти» / «Повторить» → поиск запускается немедленно через `_searchTrigger` (`SharedFlow`), `flatMapLatest` отменяет pending авто-запрос
- Сортировка: изменение порядка мгновенно пересортировывает результаты без повторного запроса к API
- Просмотренные блюда: карточки в результатах поиска помечаются галочкой, если блюдо есть в истории (реактивно из Room)

### Используемые операторы Flow

| Тип | Операторы |
|-----|----------|
| Объединение | `combine` (3 потока), `merge` (2 потока) |
| Преобразование | `map`, `flatMapLatest` |
| Управление потоком | `debounce`, `distinctUntilChanged`, `filter` |
| Подписка | `stateIn`, `onStart` |

### StateFlow vs SharedFlow

- **StateFlow**: `_query`, `_sortOrder`, `homeScreenState`, `history` — долгоживущее состояние с актуальным текущим значением
- **SharedFlow**: `_searchTrigger` — поток действий пользователя (retry, ручной поиск); нет «текущего значения», каждое событие обрабатывается ровно один раз

### Новая функциональность
- Поиск по мере ввода с debounce (500ms)
- Сортировка результатов: по умолчанию / А→Я / Я→А (чипы на экране поиска)
- Пометка просмотренных блюд в результатах поиска (реактивное объединение с Room-историей)

### Адаптированные тесты
- `14` юнит-тестов (8 существующих адаптированы + 3 новых + 3 Repo)
- Новые тесты:
